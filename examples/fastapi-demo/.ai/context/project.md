## Business objective

Small task-management API showing how a project generated by the AI Software Engineering Kit
looks and is developed. It is a teaching example, not a product.

## Problem

New developers need a concrete, runnable reference showing the kit's conventions applied:
layered architecture, tests, problem-details errors, health probes, CI and Kubernetes manifests.

## Users

Developers onboarding on the kit (internal, a few dozen).

## Functional requirements

- Create a task with a title (1-200 characters).
- List tasks with pagination (`limit` 1-100, `offset` >= 0).
- Get a task by id; complete a task (completing twice is a 409 conflict).

## Non-functional requirements

- Stateless HTTP layer; storage behind a repository port (swappable adapter).
- 100% of business rules covered by unit tests; API covered by integration tests.
- Liveness and readiness probes for Kubernetes.

## Technology stack

- **Profile:** Backend API — HTTP API exposing business capabilities (REST/JSON).
- **Technology:** Python + FastAPI (served by uvicorn behind NGINX)
- **Database:** None (in-memory adapter, see ADR 0002)
- **Deployment:** Docker + Kubernetes (RKE Staging and Prod)

## Architecture

Modular monolith with layered / clean architecture
(API -> Application -> Domain <- Infrastructure). Details: `docs/architecture/README.md`.

## Database

None: tasks live in memory and are lost on restart. A PostgreSQL adapter would implement
`TaskRepository` without changing the domain or application layers.

## External services

None.

## Security requirements

No authentication (demo only, never exposed publicly). Strict input validation
(`extra="forbid"`), no secrets required. Container runs as non-root with a read-only root FS.

## Performance requirements

Not critical. Pagination is mandatory on list endpoints (max 100 items).

## Deployment

Docker image built in CI on git.netsf.fr, deployed to RKE Staging, then the same image is
promoted to RKE Prod (manual approval). Manifests in `deploy/k8s/`.

## Constraints

Must stay small enough to read in 15 minutes.

## Risks

Being copied as-is into production without authentication or persistence. Mitigation: this file
and the README state that it is a demo.
